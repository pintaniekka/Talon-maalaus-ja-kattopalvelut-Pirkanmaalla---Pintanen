# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing/lead-gen website for Pintanen Oy, a roof-coating/cleaning and house-painting company in Pirkanmaa, Finland (pintanen.fi). It's a Vite + React + TypeScript SPA, built with shadcn-ui and Tailwind, whose pages are prerendered to static HTML at build time. Content and UI copy are in Finnish. The site was originally built with Lovable; since October 2026 it has no Lovable or Supabase dependency: images are local files and the contact form is a Cloudflare Pages Function.

## Repository and deployment

- **One repository**: `Pintaniekka/Talon-maalaus-ja-kattopalvelut-Pirkanmaalla---Pintanen` (public). Local clone: `~/GitHub/pintanen-fi`. Keep the clone **outside** `~/Documents`: iCloud sync creates "file 2" duplicates there, also inside `.git`, which breaks git.
- **Cloudflare Pages** project `talon-maalaus-ja-kattopalvelut-pirkanmaalla---pintanen` is connected to this repo by Git integration. A merge to `main` deploys to `https://pintanen.fi`. Every other branch gets a preview at `https://<branch>.talon-maalaus-ja-kattopalvelut-pirkanmaalla---pintanen.pages.dev` (served with `x-robots-tag: noindex`).
- **Workflow**: branch `claude/…` → **draft** PR to `main` while you are still pushing → mark it ready for review when the work is done (this runs E2E once) → wait for the "Cloudflare Pages" and CI checks → verify the preview → merge → verify production. `python3 scripts/verify_live.py <url> <dir>` followed by `python3 scripts/verify_dist.py <dir>` checks all sitemap pages without JavaScript (status, head values, links, images, llms.txt, schema).
- Cloudflare installs dependencies with **bun** (`bun.lock`). When dependencies change, update both `bun.lock` and `package-lock.json`, or the Cloudflare build fails on the frozen lockfile.
- **Old URLs**: `legacyRedirects` in `src/data/routes.ts` is the single source. The build plugin writes `dist/_redirects` from it (two rules per old path, with and without trailing slash, target always with trailing slash so there is one 301 and no 308 chain), `App.tsx` renders `<Navigate>` routes from the same list, and `routes.test.ts` checks every target is canonical. `public/_redirects` holds only rules that cannot be derived from the list plus the SPA fallback (last line); since 26.10.2026 it also holds the 301 rules for renamed image files (`/images/...`, see `docs/kuvien-uudelleennimeys-2026-10-26.md`), which the tests and `verify_redirects.py` skip. No `index.html` shells are generated for old paths any more (they returned 200 with the home title and Google indexed them). `python3 scripts/verify_redirects.py --file dist/_redirects --sitemap dist/sitemap.xml` checks the file; `python3 scripts/verify_redirects.py <url>` checks a preview or production (expects one 301 per rule).
- `public/_headers` sets security and cache headers; `public/_routes.json` limits Pages Functions to `/api/*`.
- **CI**: `.github/workflows/ci.yml` is the only PR workflow (E2E was merged into it on 30.10.2026). Job `tarkistus` runs tsc, lint, tests, build, `verify_dist.py`, `verify_links.py` and `verify_redirects.py` on every PR push (about 1 min). Job `e2e` runs Playwright against that same build (the `dist` artifact), only when the PR is not a draft and changes more than content: a PR that touches only `docs/`, `src/data/`, `src/content/`, `src/test/`, `scripts/`, `public/images/` or `*.md` skips it. A draft can run E2E by hand (Actions → CI → Run workflow → branch). Job `esikatselu` waits for the Cloudflare preview and runs `verify_live.py` + `verify_dist.py` against it. A new push cancels the PR's running checks. Skipped jobs show as green; `main` has no required status checks. On every push to `main`, job `lastmod` commits the build's `src/data/lastmod.json` as `github-actions[bot]` with a message starting `[skip ci]`, so neither GitHub Actions nor Cloudflare build that commit again (Eki 30.10.2026: the bot may commit this one file straight to `main`). GitHub skips every workflow for a push or PR whose newest commit message contains that marker anywhere, so never write it in a PR's commit messages (it happened on 30.10.2026). GitHub Pages is not used (the site is on Cloudflare); the "pages build and deployment" job is a leftover setting that the owner turns off in Settings → Pages (only he can). `.gitattributes` forces LF line endings (Windows checkouts broke `assetsFunction.test.ts` otherwise).
- The old working repo `Pintaniekka/easy-web-start-62` and its sync workflow are retired. Do not push there.
- Secrets (`RESEND_API_KEY`, `LEAD_INTAKE_SECRET`) live in the Pages project settings. Never print, paste or commit secret values; the owner runs secret-related commands himself.

**End-to-end tests (`tests/e2e/`, Playwright).** They run against the built site: `npm run build`, then `npm run test:e2e` (the config starts `vite preview` on 127.0.0.1:4173 itself; `--project=puhelin` or `tyopoyta` for one width, `-g "Hintalaskuri"` for one group, `--ui` to watch). The full-page screenshot comparison was removed on 29.10.2026 (Eerik): baselines were never usable and the layout changes too often. Every test mocks `/api/contact` through `tests/e2e/fixtures.ts`, so no lead is ever sent; new tests must use the `contact` fixture, never a real request. The chat timers are shortened with `shortenChatTimers`, not `page.clock` (it freezes framer-motion exits). The `e2e` job in `.github/workflows/ci.yml` runs both specs in the `mcr.microsoft.com/playwright:v1.63.0-noble` image (see **CI** above for when), uploads the report as an artifact and comments the PR with the links. The Playwright version is pinned exactly in `package.json`; when bumping it, change the Docker image tag too. Locally Playwright needs its browser: `npx playwright install chromium` (in the cloud sandbox it is preinstalled under `/opt/pw-browsers`).

## Architecture

**Routing is generated from city data, not hand-written per page.** `src/data/cityData.ts` exports `cities` (8 "full-service" cities with dedicated pinnoitus/puhdistus/maalaus subpages) and `allCities` (24 cities total, all get a unified area page). `src/App.tsx` maps over these arrays to produce `<Route>` entries for:
- 3 static service pages for the Pirkanmaa region (`/tiilikaton-pinnoitus-pirkanmaa`, `/katon-puhdistus-pirkanmaa`, `/talon-maalaus-pirkanmaa`)
- Per-city service pages for full-service cities (`KattopalvelutPinnoitusCity`, `KattopalvelutPuhdistusCity`, `TalonMaalausCity`, parameterized by `citySlug` prop, not a router param)
- Per-city area pages for all 24 cities via one shared template, `ServiceAreaPage`
- A block of `<Navigate replace>` redirects from old URL patterns (`/kattopalvelut/...`, `/alue/:city`, `/hinnat/...`) to the new slugs above

**When adding or renaming a route, add it to `src/data/routes.ts` as well.** That file is the single source for `vite-plugin-spa-routes.ts`, which at build time copies `dist/index.html` into every route's directory (so static hosting serves 200s for deep links), strips the home-only hero preload (`data-home-only` in `index.html`) from subpage copies, writes `dist/404.html` (= index.html, so unknown paths render the SPA's Finnish 404 page with a real 404 status) and generates `dist/sitemap.xml`. `src/test/routes.test.ts` fails if a literal `path="..."` in `App.tsx` is missing from `routes.ts`. There is no hand-maintained `public/sitemap.xml` any more.

Per-city copy (SEO titles/descriptions, intro text, local "hook" paragraphs) lives alongside the city definitions in `src/data/cityData.ts`, `areaCityContent.ts`, `cityNeighborhoods.ts`, `faqData.ts`, and `testimonialsData.ts` — these are large content tables, not logic; page components pull from them via slug lookups (`getCityBySlug`, `getAreaCityContent`, etc.).

**Images are the site's own files in `public/images/`**, served at `/images/…` (30-day cache, see `public/_headers`). Folders: `Pictures-400|600|800|1200|1500/` (responsive WebP, file name `<base>-<width>.webp`), `Pictures-200/` (portraits), `Eerik-maalaa/` (home hero, AVIF), `Icons/`, plus logo, favicon and map in the root. `src/lib/storage.ts` builds the URLs: use `getStorageUrl`, `getResponsiveSrc` and `getResponsiveSrcSet`, and render through `OptimizedImage`/`ResponsiveImage` rather than raw `<img>`. Social tags, JSON-LD and the image sitemap need absolute URLs: use `toAbsoluteUrl`. Image base names follow the pattern `<palvelu>-<paikkakunta>-<kuvaus>` (e.g. `tiilikaton-pinnoitus-tampere-harmaa-tiilikatto-ennen`; Eerik 26.10.2026). To add an image, add the 400, 600, 800 and 1200 px files and refer to it by base name; `src/test/seo.test.ts` fails if a size is missing. The 600 px size was added on 26.10.2026: `python3 scripts/taydenna_kuvakoot.py` makes it from the 1500 or 1200 px file with a per-image quality that keeps it between the 400 and 800 px file sizes, skips images whose 800 px file is already so small that a 600 px file would not be smaller, and writes the exceptions to the generated `src/data/kuvakoot.ts`, which `getResponsiveSrcSet` and the test read. New photos: Eerik drops originals in `~/GitHub/uudet-kuvat/`; run `python3 scripts/lisaa_kuva.py <original> <base-name>` to generate the 400/600/800/1200(/1500) WebP sizes (strips EXIF/location, handles HEIC, converts iPhone Display P3 to sRGB), then reference the image by base name. **AVIF (Eki 30.10.2026):** for every photo that has a full-size original, run the script with `--avif --alkuperainen --laatu 80`: it also writes `<base>-<width>.avif` next to the WebP files (quality 56, libaom speed 2 = the measured knee of the quality/size curve; about 25 % smaller than Cloudflare's transformation at the same SSIM), regenerates `src/data/avifkuvat.ts`, and keeps the full-size source (long side 2400 px) in `alkuperaiset/` at the repo root (not deployed). `--vain-avif` adds AVIF to an existing image without touching its WebP files. `OptimizedImage`, `ResponsiveImage` and `AvifKuva` (wrap any other `<img>` that has a `srcSet`) render `<picture className="contents">` with an `image/avif` source derived from the WebP srcset (`avifVastine`), so about 95 % of browsers get AVIF and the rest WebP; the hero preload uses `type="image/avif"` when the hero has AVIF. Never re-encode an image that has no original: the 133 older photos stay WebP until Eerik sends originals (list: `Claude outputs/vanhat-kuvat-2026-10-30.html`). Cloudflare's image transformation was tried on 30.10. and replaced by this the same day. Details and the 30.10. renames: `docs/kuvien-uudelleennimeys-2026-10-30.md`.

**Layout (Eerik 28.10.2026, "ehdotus 2").** Three block types and one card, all in `src/index.css`: `.osio` is a block whose background comes from the `Rytmi` wrapper (`src/components/Rytmi.tsx`), which alternates white and a very light cool grey ("sumu", `--accent-light` #f5f7fa; the old light blue #ecf7ff was dropped 28.–29.10.2026) over the page's blocks in order and turns blocks marked `merkitse(Component, "sininen" | "navy")` into full-colour stages with gentle slanted edges (`.viisto`, 40 px desktop, 20 px phone; the wedge is filled with the neighbours' colours, and two stages never land next to each other). Blocks marked `"oma"` keep their own background (heroes, `Lyhyesti`, `ToimintaAlueetBanner`, `KotitalousVahennys`); `"ohita"` renders nothing. `.kortti` is the only card (white, rounded, soft shadow; it resets the colour variables, so it also works on blue and navy), with `.kortti-numero` (blue number circle) and `.kortti-merkki` (light-blue icon circle). Pages wrap their blocks in `<Rytmi>`; a new block component should use `className="osio"` and no background class, and long SEO texts use a narrow column with one fact beside it (`PinnoitusSamaTyo`, `MaalausSanasto`). Stage blocks: `PinnoitusWhyNow`, `MaalausCitySigns`, `MaalausProblemSection`, `MiksiValitaPintanen`, `MiksiPintanen` (blue) and the two entrepreneur blocks (navy). `ToimintaAlueetBanner` and `Lyhyesti` stay as they are (Eerik). Every page ends FAQ → contact → `ToimintaAlueetBanner` (Eerik 28.10.2026). Two stages never sit next to each other (the second falls back to a plain block), so order blocks with a plain one between stages; numbers that must be yellow on a stage and blue on a plain block use `.luku-korostus`. Before/after labels use `EnnenJalkeenMerkki`; a `pair` (slider) only when both photos share the framing, otherwise `before`/`after` side by side.

**Page metadata lives in `src/data/seo.ts`** (title + description per route, `getRouteSeo(path)`, hero image per template). Pages spread it into `<SEO>`, and the build plugin writes the same values into each route's static HTML (title, description, canonical, og/twitter tags, hero-image preload with srcset) so readers that do not run JavaScript see page-specific data. `src/main.tsx` removes those static tags before React renders, so the rendered DOM never has duplicates. The plugin also generates `sitemap.xml`: every page's `lastmod` comes from `src/data/lastmod.json`, a manifest the build maintains by hashing each page's prerendered `<main>` content (changed content = build date, unchanged = stored date; articles use the newer of `updatedAt` and that date). **Do not commit `src/data/lastmod.json` in a PR**: a local build changes it, so restore it before committing (`git checkout -- src/data/lastmod.json`). The CI bot commits it on `main` after each merge (since 30.10.2026; before that every PR committed it and PRs kept conflicting). CI warns if a PR changes it. `SITE_UPDATED` in `company.ts` is only the visible "Päivitetty" line. Katon puhdistus pages are priority 0.3 / yearly (service ended). It also writes, `image-sitemap.xml` (each page's real hero image), `llms.txt` and `llms-full.txt` (the visible text of every prerendered page, `buildLlmsFullTxt`/`htmlToPlainText` in `routes.ts`; `verify_live.py` checks it). `public/_headers` sets security and cache headers on Cloudflare Pages. `ServiceSchema` adds `Service` JSON-LD on service and city pages; `SEO` adds a two-level `BreadcrumbList`; the business entity in `index.html` has `@id` `https://pintanen.fi/#yritys`. `RelatedArticles` links service and price pages to published articles. `src/test/seo.test.ts` and `routes.test.ts` guard all of this (every route has metadata, unique titles, hard-coded internal links resolve).

**SEO** is handled per-page via the `SEO` component (`src/components/SEO.tsx`), which sets title/description/canonical/OG tags through `react-helmet-async`, defaulting to Pintanen's site-wide title/description when a page doesn't override them. Pass `noindex` for pages that must not be indexed (404).

**Forms & privacy**: every lead form (`ServiceContactSection`, `DesktopQuoteDrawer`, `ChatLeadForm`, `ChatPriceCalculator`) goes through `submitContactForm` in `src/lib/contactForm.ts`, which POSTs JSON to `/api/contact`. That is a Cloudflare Pages Function, `functions/api/contact.ts`: it emails `myynti@pintanen.fi` via Resend (reply-to = the customer) and forwards the lead to the CRM (`https://app.pintanen.fi/api/public/vastaanota-liidi`, bearer `LEAD_INTAKE_SECRET`). A CRM failure never fails the form (the email still goes out and the error is logged); a Resend failure returns an error so the form does not claim success. The function only accepts requests whose `Origin` is pintanen.fi, localhost or this project's `*.pages.dev` previews, and silently drops submissions where the hidden honeypot field `website` is filled (`HoneypotField` in `src/components/FormPrivacyNote.tsx`). Checks run in the order origin → method → body → honeypot → fields → secrets, so rejections can be tested where no secrets exist. The function deploys with the site; there is nothing to deploy separately. **Never send a real test submission without the owner's permission**: it reaches the real sales inbox and the CRM. Test with rejected requests instead (wrong origin → 403, honeypot → silent success, missing name → 400); `src/test/contactFunction.test.ts` covers the rest with `fetch` mocked. Forms show `FormPrivacyNote` linking to `/tietosuoja` (`src/pages/Tietosuoja.tsx`); keep that page accurate if data processing changes. Fonts are self-hosted via `@fontsource/*` imports in `src/main.tsx`. Apart from Google Analytics 4 (`src/lib/analytics.ts`), which loads only after cookie consent, the site makes no requests to third-party hosts (Cloudflare Web Analytics was turned off on 30.10.2026, Eki; do not re-enable it in the Pages project).

**Build output**: `vite.config.ts` manually chunks vendor bundles (`vendor-react`, `vendor-ui`; framer-motion's features load lazily as the `motionFeatures` chunk through `LazyMotion` in `App.tsx`, PR #139) and layers one custom plugin on top of the React/SWC plugin: `vite-plugin-spa-routes.ts` (static route mirroring, described above). The whole stylesheet is inlined into every route's HTML (`inlineStylesheet`, Eki 30.10.2026), so there is no render-blocking CSS request and no flash of unstyled content (an earlier async-CSS trick caused one and was removed on 7.10.2026; never inline only a critical subset). The app's module script and modulepreloads get `fetchpriority="low"` (`applyScriptPriority`) so the font and hero image load first. Hydration waits for the framer-motion features (`motionFeaturesPromise` in `main.tsx`), otherwise React threw #418/#421 on lazy pages. `src/entry-prerender.tsx` collects React's stream through a `StringDecoder` and strips NUL bytes: React's stream splits UTF-8 characters at chunk boundaries and pads chunks with NUL when a multi-byte character does not fit (found 28.10.2026 in 16 pages). Most page components are lazy-loaded via `lazyWithRetry` (`src/lib/lazyWithRetry.ts`) rather than plain `React.lazy`.

## Articles (`/artikkelit`)

Articles are data-driven and deliberately text-first: no hero, no CTA buttons, no trust stats, no contact form. One shared template renders every article.

- `src/data/articles.ts` — metadata for every article (slug, title, lead, description, category, author, `publishedAt`, `updatedAt`, reading time, hero image). Must stay free of component imports: the Vite plugin reads it in Node at build time.
- `src/content/articles/<slug>.tsx` — the body, default-exported. Write plain `h2`/`h3`/`p`/`ul`/`ol`/`blockquote` plus the helpers in `src/components/article/ArticleKit.tsx` (`Figure`, `KeyPoints`, `Note`, `ArticleFaq`). Internal links are inline `<Link>`s in the prose. Do not add buttons, stat grids or forms.
- `src/content/articles/index.ts` — registers the body under its slug (lazy-loaded).
- `src/components/article/ArticleLayout.tsx` — the template: breadcrumb, category, H1, lead, byline (author, dates, reading time), hero figure, auto-generated table of contents from the body's `h2`s, prose (`.article-prose` styles in `src/index.css`), one quiet closing paragraph per category, author box, "Lue myös". Emits `Article` + `BreadcrumbList` JSON-LD.
- `src/pages/Artikkeli.tsx` serves `/artikkelit/:slug`; `src/pages/Artikkelit.tsx` lists published articles.

**Scheduling**: an article whose `publishedAt` is in the future is "queued". The build still creates its route directory, but the page renders the 404 and the list hides it until that date (Finnish time), so it goes live on its date without a new deploy. **But the static HTML shell keeps the queued `noindex` and the page is missing from `sitemap.xml` until the next production build.** `.github/workflows/julkaise-jonossa.yml` runs every morning and, on a day that matches an article's `publishedAt`, triggers a Cloudflare Pages production build through the deploy hook in the GitHub secret `CF_DEPLOY_HOOK_URL` (the owner creates and sets it; without it the workflow only warns). It can also be run by hand from the Actions tab. `src/test/routes.test.ts` checks that every article has a body file, a registry entry and valid metadata. A queued article can be read before its date at `/artikkelit/<slug>/?esikatselu=1` (rendered `noindex` with a preview banner).

**Writing style for articles** (Finnish): write as the tradesman whose byline is on the article, in first person plural ("teemme", "annamme", "meillä"), in plain, direct Finnish. Avoid formulaic AI phrasing: no "tässä artikkelissa käydään läpi", no "ei vain X, vaan Y", no rhetorical set-ups, no padded summaries. For search engines and AI answers: the lead and `KeyPoints` answer the title's question directly with concrete numbers; `h2`s are phrased as the questions people search for; prices go in a `Table`; every article ends with `ArticleFaq`, and externally sourced facts are listed with `Sources`. Mention Pirkanmaa where it is natural. `ArticleKit` also exports `Table` and `Sources`.

**Fact rule for article content**: never invent anything about Pintanen Oy. Company facts (prices, warranty, process, materials, durations) must come from what the site already states (`src/data/faqData.ts`, the price pages, the calculators). General facts (tax rules, paint manufacturers' limits) must be checked against a source on the web before writing; if a fact cannot be verified, leave it out. Cadence: two articles per week, published on Mondays and Thursdays (Eerik 26.10.2026; earlier one per week on Tuesdays). Content mix: about 65 % roof topics, 35 % walls/facades; no further roof-cleaning articles. After the painting season ends, titles use the coming season's year.

## Sisältösäännöt (Eerikin päätökset, suomeksi)

Nämä koskevat kaikkea sivuston tekstiä. Ne ovat omistajan antamia ja ohittavat yleiset oletukset.

**Ei keksittyä tietoa.** Yrityksestä saa sanoa vain sen, mikä on tässä repossa tai Eerikiltä saatu: ei keksittyjä lukuja, referenssejä, kohteita, arvosteluja tai paikkakuntakohtaisia kohdemääriä. Yleiset faktat (kunnat, tilastot, materiaalit) vain tarkistetuista lähteistä; lähteet kirjataan `docs/`-kansioon. Arvostelut (`src/data/testimonialsData.ts`) ovat Google-arvosteluja sanasta sanaan: älä lyhennä äläkä muokkaa.

**Kieli.** Todella yksinkertaista ja luonnollista suomea: lyhyet virkkeet, arkiset sanat, me-muoto ja lukijan sinuttelu. Ei luettelomaista sähkösanomatyyliä eikä geneerisiä yleistyksiä. Olemassa olevat tekstit on tarkastettu käsin: älä tee niihin isoja muutoksia kysymättä. Pieni faktakorjaus on eri asia, mutta kerro mitä muutit. Ei "emme tee" -lauseita eikä puutteiden mainostamista.

**Hinnat.** Pinnoituksen yleinen haarukka 2 850–7 000 € ja maalauksen 3 500–11 000 € (`src/data/prices.ts` on ainoa lähde). Hintakortteihin ja niiden schema-vastineisiin ei kosketa. Ei "alk." yhdessä haarukan kanssa, ei minimihintaa, ei hinnastoja eikä laskuesimerkkejä. Neliöhinnat pinnoitukselle katon koon mukaan ovat sallittuja (27.10.2026), ei muita neliöhintoja. Hintakorttien "alk."-luvut lasketaan 40 %:n vähennyksellä ilman omavastuuta; hintasivujen esimerkkitaulukot käyttävät korttien lukuja. Käyttöikä: "jopa 15 vuotta" (Eerik 26.10.2026; aiemmin 15–20). Pinnoitus on ajankohtainen "noin 15 vuoden iässä" (Eerik 26.10.2026; aiemmin 10–15, Eerik 11.10.2026): 15 vuotta lisäikänä on eri asia kuin katon ikä. Puutalon maalausväli on edelleen 10–15 vuotta. Ei "Pirkanmaan tyytyväisimmät asiakkaat". Kattoremontin hinta 15 000–30 000 € on sallittu (lähteet `docs/`-kansiossa).

**Yritys.** Pintanen on tamperelainen yritys (Eerik 5.10. ja 11.10.2026). Oulua tai muuta kotipaikkaa ei mainita missään; `seo.test.ts` estää sanan. Meistä-sivulle ei lisätä perustamispäivää, vakuutuksia tai rekistereitä.

**Tiilikaton pinnoitus (Eerik).** Pinnoitus ja maalaus tarkoittavat samaa työtä; molempia sanoja käytetään. Työnkulku: ilmainen kuntotarkastus → painepesu → kasvustontorjunta-aine → rikkinäiset tiilet vaihdetaan uusiin → pohjamaali ja pintamaali korkeapaineruiskulla (aina kaksi kerrosta), reunat telalla. Maali: vain Nowocoat. Aluskate ja läpiviennit tarkistetaan aina. Katto maalataan kahteen kertaan; reunat maalataan käsin ja vain kerran, joten reunoista ei sanota mitään (ei "myös reunoihin", ei "vain kerran"; Eerik 27.10.2026). Kiellettyjä sanoja katosta: tehopesu, pohjuste, pohjustus, primer. Älä väitä, että seinät tai piha suojataan (joskus suojataan aurinkopaneelit, valokatteet tai lasiterassit). **Paikallinen ajo ja PR:ien niputus (Eki 30.10.2026).** CI ajaa jokaisessa PR:ssä tsc:n, lintin, vitestin, buildin ja `verify_*`-skriptit, ja valmiissa PR:ssä E2E:n: älä aja samaa settiä paikallisesti uudestaan.
